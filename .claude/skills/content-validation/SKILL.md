# Валидация контента

`bun run validate` = сборка YAML → `build/world.json` (zod-парсинг, падает на ошибке схемы) → правила → симуляция.
Падает с кодом 1 при любой ошибке. Предупреждения не роняют.

## Правила (`packages/validator/src/rules/`)

| Правило | Что ловит | Уровень |
|---|---|---|
| `qualities` | условие или эффект на необъявленное качество, в том числе в `rules.*` (включая `pledgedNightWhen` и `tensionWhen`), `report.notes`, `morning.notes`, `notebook` и эпилогах концовок; `rules.clock.quality` не объявлено; `rules.start` указывает на несуществующую локацию | error |
| `references` | `goto` выбора или перехвата на несуществующую локацию; `background`/`portrait` нет в `assets.json` | error |
| `dead-ends` | локация без сторилетов (error); сторилет, у которого все choices условные (warning) | error / warning |
| `reachability` | локация, недостижимая из `rules.start` по графу `goto` (условия игнорируются) | warning |
| `report-slots` | слот отчёта без фрагментов или без фолбэка (фрагмента без условий) | error |
| `layouts` | `layout: doors` не с тремя choices или дверь без `goto`; `layout: pledge` без `memories` в мире или без безусловного `endNight`-выбора | error |
| `placeholders` | `{…}` в тексте сторилета, выбора, `outcome`, фрагмента, пометки отчёта, страницы блокнота или карточки улики, не являющийся объявленным качеством | error |
| `memories` | пара с повторным `id`, необъявленным, одинаковым или повторно использованным флагом, `returnWhen` на необъявленное качество; мир с парами без `pledged.*`, `returned.*`, `returned_tonight`, `memories_returned` | error |
| `notebook` | повторный `id` страницы; `when` страницы или `life.footer` на run-качество (закрылись бы на следующую ночь); плейсхолдер в `life.states` кроме `{label_fake}`/`{label_real}` | error |
| `self-exclusion` | выбор без `goto`/`endNight` ломает `when` своей карточки, а другие остающиеся выборы нет: после него карточка сменится посреди сцены и соседние вопросы пропадут. Не срабатывает, если флаг ставят все остающиеся выборы (карточка на один показ) или у карточки `intro: true` | warning |
| `planned` | условие на качество, которое ничего не ставит (ни эффект, ни правило, ни движок) и у которого default 0. Обычно контент будущих этажей | warning |
| `evidence` | повторный `id` карточки; `flag` на необъявленное качество; `image` нет в `assets.json`; мир с уликами без `found.*` | error |
| `endings` | `ending` выбора не из `endings.yaml`; `ending` вместе с `endNight`; повторный id концовки; картинки нет в `assets.json`; `endings.*` или `ending_night` не объявлено; `opening_slot`/`litany_slot` не из слотов отчёта | error |

Тупики по состоянию (нет подходящего сторилета, нет доступных выборов) ловит симуляция, а не статическое правило: условия вида `seen.x == 0` / `seen.x == 1` или набор `floor == 1..4` дополняют друг друга, и статически это не видно. Поэтому «все выборы условные» — warning, а `stuck` в симуляции — error.

Ожидаемые предупреждения на полном мире (этажи 1–12, подвал, тринадцатый): только «все выборы условные» у четырёх лестниц (`stairs`, `stairs_upper`, `stairs_grate`, `stairs_top`), `planned` быть не должно. Случайный игрок за 200 ночей не доходит до верхних этажей и концовок (`by ending: 0`, в «never shown» карточки Владельца, тринадцатого, финала): до них доходят направленные маршруты кампании в `belvedere-night.test.ts`, автор проверял 110 000 ночей.

Каждое правило — функция `(world, assets) => Issue[]`, `Issue = { level, where, message }`.

## Добавить правило

1. Файл `rules/<name>.ts`, экспорт `check(world, assets): Issue[]`.
2. Добавь в список в `rules/index.ts`.
3. Тест в `packages/validator/test/<name>.test.ts` на мини-мире из трёх сторилетов: один проходит, один ломает.
4. Строка в таблицу выше.

## Симуляция

`simulate.ts` прогоняет N ночей (по умолчанию 200) со случайным выбором через engine: экраны `outcome` пролистываются, на `pledge`-экране случайно выбирается воспоминание или обычный выбор; профиль тянется через 5 ночей подряд, потом сбрасывается. Печатает:

```
simulated 200 nights
  ended by memory pledge: 120, by endNight choice: 80, by ending: 0, stuck: 0, errors: 0
  turns per night: min 1, avg 5.7, max 17
  storylets never shown (6): lobby_late, pledge_caught, ...
  choices never taken (15): lobby_hub#1, ...
```

Как читать:
- `stuck > 0` или `errors > 0` — состояние без доступных выборов или исключение движка. CLI выходит с кодом 1.
- `never shown` / `never taken` — сторилет или выбор недостижим для случайного игрока. Либо условия слишком строгие, либо путь длинный. Решай по смыслу: случайный игрок часто уходит из башни рано.
- `turns per night` — случайный игрок выбирает «уйти» так же охотно, как остальное, поэтому среднее ниже, чем у живого игрока. `max` может быть чуть больше лимита перехвата: выбор с собственным `turn += 1` плюс `onChoice` перескакивает через 16.

Запуск с другими параметрами: `bun run packages/validator/src/cli.ts <world.json> <assets.json> --nights 1000 --seed 7`.
