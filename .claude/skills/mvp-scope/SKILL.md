# Рамки MVP

## Входит

- Пролог в конторе → фасад → вестибюль (Долли) → этажи 1–4 с экраном трёх дверей → комнаты жильцов 2–4 → служебные 3–4 → выход через залог → отчёт за ночь.
- Качества: ход ночи (16), подозрение, сигареты, улики, доверие Долли, счёт ночей, визиты дверей.
- Минимум 15 сторилетов.
- Сохранение профиля между ночами и незавершённого забега после каждого выбора (CloudStorage, фолбэк localStorage).
- Validator и golden-тест «полная ночь» зелёные.
- Mini App открывается из бота, тема и viewport Telegram, кнопка «Назад».
- Фон 9:16, нижняя треть под текст и кнопки, CSS-дождь и мерцание лампы.
- Звук через FMOD: дождь, музыка с напряжением по подозрению, щелчок зажигалки на начало ночи (ADR 0005).

## Не входит

Платежи Stars, энергия, коллекционки, концовки, итоговый рассказ, UGC/редактор, своя БД, аналитика, локализация, анимации сложнее CSS, админка, авторизация на сервере.

## Когда тянет «сделать заодно»

1. Спроси себя: без этого MVP не пройдёт критерий готовности? Если нет — это не сейчас.
2. Запиши одну строку в `docs/backlog.md`: что, зачем, где в коде точка расширения.
3. Не оставляй в коде заготовок, TODO-веток и флагов под будущую фичу. Пустой код — тоже код, его надо поддерживать.
4. Архитектура должна **не мешать** будущим фичам (UGC, другой рендер), но не обязана их **реализовывать**.

## Признаки выхода за рамки

- Новая npm-зависимость ради одной функции.
- Абстракция с одной реализацией «чтобы потом подменить».
- Конфигурация того, что в MVP имеет одно значение.
- Поле схемы, которое ни один сторилет не использует.
