# Как писать сторилеты

Контент лежит в `content/belvedere/`. Источник правды по сюжету — `docs/world-bible.md`. Не выдумывай факты мира, которых там нет.

## Файлы

- `world.yaml` — качества, локации, глобальные правила (`rules.start`, `rules.onChoice`, `rules.interrupts`, `rules.onNightEnd`), пары воспоминаний.
  Локация: `{ id, label, outdoor: true }`. `outdoor` включает дождь и зарницы поверх картинки; в помещениях флага нет, и погода не рисуется.
- `storylets/*.yaml` — список сторилетов. Один файл на локацию или тему.
- `report-fragments/*.yaml` — фрагменты отчёта по слотам.
- `notebook.yaml` — блокнот Ника: справочные страницы и шаблоны страницы «Что я о себе знаю» (см. ниже).
- `evidence.yaml` — папка улик: карточки с картинкой и заметкой Ника (см. ниже).
- `endings.yaml` — концовки и сборка итогового рассказа «Дело Хейла» (см. ниже).

Сборка: `bun run content:build` → `content/belvedere/build/world.json`. Проверка: `bun run validate`.

## Сторилет

```yaml
- id: lobby_dolly_first          # уникальный, snake_case
  location: lobby                # из world.yaml locations
  priority: 10                   # выше = важнее; при равенстве выбирает seed-RNG
  when:                          # все условия должны быть истинны (И)
    - visited.lobby == 0
    - dolly_trust < 3
  layout: scene                  # scene (по умолчанию) | doors | pledge
  background: lobby              # id из assets/assets.json
  portrait: dolly_suspicion      # необязательно; сцена 9:16 заменяет фон, квадратная улика (ev_*) ложится вставкой поверх фона
  title: Вестибюль
  text: |
    Долли смотрит на вас так, будто уже знает, зачем вы пришли. Улик при вас: {clues}.
  choices:
    - text: Показать квитанцию
      when: [has.pawn_ticket == 1]   # необязательно; невыполненный выбор скрыт
      effects:
        - dolly_trust += 1
        - suspicion -= 1
      outcome: |                       # необязательно: отдельный экран после эффектов, кнопка «Дальше», потом goto
        Долли читает квитанцию дважды. «Этого номера в книге нет». Доверие: {dolly_trust}.
      goto: floor_01                   # локация; без goto остаёмся в текущей
    - text: Промолчать и пройти к лестнице
      effects: [suspicion += 1]
      goto: floor_01
    - text: Закончить ночь
      endNight: true                   # вызывает сборку отчёта и сброс run
```

Условие: `<quality> <op> <int>`, op ∈ `== != < <= > >=`. Эффект: `<quality> <op> <int>`, op ∈ `+= -= =`.
Это не выражения языка: строка проверяется регулярным выражением в `content-schema/expressions.ts` при сборке (`bun run content:build` падает с путём до поля) и разбирается тем же regex-ом в движке. Никакого eval нет и не будет: миры могут писать чужие люди.
Качество должно быть объявлено в `world.yaml` (точно или через namespace `visited.*`). Значения только целые.

Экран трёх дверей — сторилет с `layout: doors` и ровно тремя choices, каждый с `goto`. Порядок: дверь жильца, служебная дверь, лестница. Дверь с невыполненным `when` показывается запертой и не тратит ход, поэтому «жилец не открывает при Подозрении 5» — это `when: [suspicion < 5]` на двери, а не отдельная карточка.

`rules.onChoice` из `world.yaml` применяется после эффектов каждого выбора (например `turn += 1`). Если выбор не должен тратить ход, укажи `free: true`.

**Перехваты.** `rules.interrupts` — список `{ when, goto }`. После каждого выбора (включая `free`, после эффектов и `onChoice`, а при `outcome` — после «Дальше») срабатывает первый подходящий и переносит игрока в `goto` вместо `goto` выбора. `endNight` сильнее перехвата. Ночь заканчивается **только** выбором с `endNight` или залогом воспоминания, поэтому рассвет и поимка — это перехваты в локацию залога:

```yaml
rules:
  interrupts:
    - { when: [suspicion >= 10], goto: pledge }
    - { when: [turn >= 16], goto: pledge }
```

**Подстановки.** В `text` сторилета, `text` выбора, `outcome` и `text` фрагмента `{quality_id}` заменяется числом из состояния на момент показа. Для `outcome` это состояние после эффектов. Неизвестный id — ошибка validator (правило `placeholders`). Фигурные скобки в тексте можно использовать только для подстановок.

**Экран последствия.** `outcome` у выбора: эффекты и `onChoice` применяются сразу, потом игрок видит текст с кнопкой «Дальше», и только после неё срабатывают `goto`, `endNight` и проверка `nightEndWhen`.

## Воспоминания и залог

В `world.yaml` секция `memories` — список пар:

```yaml
memories:
  - id: ring                       # по нему движок пишет pledged.ring / returned.ring
    fake: mem.false.marines        # флаг ложного воспоминания (profile, default 1)
    real: mem.true.ring            # флаг настоящего (profile, default 0)
    label_fake: Морская пехота, Тихий океан
    label_real: "Кольцо: свадьба на Канал-стрит"
    returnWhen: [has.ring == 1]    # если выполнено в момент залога — настоящее возвращается
```

Ключи именно `fake`/`real`: по YAML 1.2 `false:`/`true:` — булевы значения. Оба флага должны быть объявлены в `qualities` (обычно namespace `mem.false.*` с `default: 1` и `mem.true.*`). Движок смысла пар не знает. При залоге пары `X` он: ставит `fake` в 0 и run-флаг `pledged.X = 1`; если `returnWhen` выполнено — `real = 1`, `returned.X = 1`, `memories_returned += 1`; затем завершает ночь. Отчёт собирается до сброса run, так что фрагменты могут смотреть на `pledged.*` и `returned.*`. Мир с парами обязан объявить `pledged.*`, `returned.*`, `returned_tonight` (run) и `memories_returned` (profile), иначе validator падает.

Сторилет с `layout: pledge` показывает кнопку на каждое ложное воспоминание со значением 1 плюс свои обычные `choices`. Обязателен хотя бы один безусловный `endNight`-выбор — «Заложить ночь» (`effects: [night_pledged = 1]`, воспоминания не трогаются; фрагменты отчёта смотрят на `night_pledged`).

## Подсказки, цена выбора, пометки отчёта

- `hint` у качества в `world.yaml` — одна строка, которую приложение показывает под HUD при **первом за всю игру** изменении качества (и для невидимых тоже). Что уже показано, помнит приложение, не мир. Висит столько, сколько нужно прочитать: слова ÷ 180 слов в минуту + 5 секунд (`readingTime` в ui-kit), тап закрывает сразу; длина строки влияет только на время показа.
- Цена выбора на кнопке считается сама: прирост качества-часов (то, что `rules.onChoice` увеличивает, у нас `turn`) от эффектов выбора плюс `onChoice`. `free: true` → пометки нет; `turn += 1` в эффектах → «2 хода». `max` у качества ограничивает и эффекты: `turn` не уйдёт за 16.
- `report.notes` — список `{ when, text }`; все подходящие строки печатаются мелко над отчётом. Условия могут смотреть на run (отчёт собирается до сброса).
- `morning.notes` — тот же формат, строка-итог под заголовком «Утро». Условия тоже проверяются по состоянию отчёта, так что доступны `night_pledged`, `pledged.*`, `returned.*` и run-флаг `returned_tonight` (движок ставит его в 1 при возврате воспоминания этой ночью; `memories_returned` считает за всю игру). Делай условия взаимоисключающими, чтобы строка была ровно одна.

## Блокнот (`notebook.yaml`)

```yaml
life:                                  # страница «Что я о себе знаю», собирается из memories
  title: Что я о себе знаю
  intro: …
  states:                              # шаблон строки по состоянию пары; плейсхолдеры только {label_fake} и {label_real}
    fake: "{label_fake}"               # ложное на месте
    empty: "~~{label_fake}~~ — пусто"  # заложено, настоящее не вернулось; ~~…~~ рисуется зачёркнутым
    real: "~~{label_fake}~~ → {label_real}"   # после → другой почерк
  footer:                              # подпись внизу; when только по profile-качествам
    when: [memories_returned >= 1]
    text: …
pages:
  - id: eddie
    title: Эдди Мэлоун
    when: [visited.floor2.tenant >= 1]  # только profile-качества, иначе validator error: страница пропала бы на следующую ночь
    text: голос Ника
    rule: как это работает, простыми словами
```

Страницы без `when` открыты сразу. Закрытые не показываются, внизу «Ещё страниц: N». Новая открытая страница даёт точку на иконке блокнота, пока её не прочитали. Люди и места открываются после встречи через profile-флаги `met.*` (их ставят эффекты карточек встречи); те же флаги делают карточку одноразовой (`office_ring` при `met.office_ring == 0`).

**Флаг, который выводит карточку из выбора, ставится только на выборе с `goto`** (или на каждом остающемся выборе, если карточка нарочно на один показ: после любого ответа её сменяет хаб). Выбор без `goto` остаётся в той же локации, движок заново выбирает карточку, и если вопрос поставил `met.x = 1` при `when: [met.x == 0]`, игрок после «Дальше» увидит другую карточку, а остальные вопросы пропадут. Validator предупреждает об этом (`self-exclusion`); одноразовое интро с вопросами можно пометить `intro: true`.

После отчёта приложение показывает «Утро»: страницу «Что я о себе знаю», где строка, заложенная этой ночью, зачёркивается на глазах, а вернувшееся дописывается другим почерком. Данные берутся из `pledged.*`/`returned.*` до сброса run, контенту делать ничего не нужно.

## Папка улик (`evidence.yaml`)

```yaml
items:
  - id: ring
    order: 20                 # порядок в папке, не время находки
    flag: has.ring            # run-качество «найдено этой ночью»
    image: ev_ring            # id из assets.json, необязательно
    title: Обручальное кольцо
    text: |                   # заметка Ника; пустая строка делит абзацы
      Тонкое золото, внутри гравировка…
```

Когда `flag` впервые становится 1, движок ставит профильный `found.<id> = 1` (мир с улика́ми обязан объявить `found.*`, scope profile). Папка показывает найденные карточки по `order`, найденное этой ночью помечено «сегодня», внизу «Ещё улик: N». Новая карточка даёт точку на иконке папки. Validator: `flag` объявлен, `image` есть в `assets.json`, id уникальны.

## Концовки и «Дело Хейла» (`endings.yaml`)

Выбор с `ending: <id>` завершает игру (вместе с `endNight` нельзя). Приложение сначала спрашивает подтверждение, потом показывает `outcome`, экран концовки и рассказ. Движок ставит `endings.<id> = 1` (объяви `endings.*`, scope profile) и run-флаг `ending_night = 1` перед отчётом (объяви его; фрагменты вроде `twist_final`/`price_final` смотрят на него), закрывает ночь как обычную (отчёт попадает в рассказ) и больше ничего не знает. Цена хода на кнопке концовки не показывается.

```yaml
endings:
  - id: case_closed
    title: Дело закрыто
    image: ending_case_closed     # 9:16 из assets.json
    text: |                       # голос отчёта, абзацы через пустую строку
      …
    epilogues:                    # все подходящие по when; могут смотреть на endings.* прошлых дел
      - { when: [], text: … }
      - { when: [endings.redemption == 1], text: … }
story:
  title: Дело Хейла
  parts: [opening, nights, pledged_note, litany, ending, epilogues]   # порядок; closing всегда в конце
  opening_slot: client            # необязательно: по умолчанию первый слот отчёта
  litany_slot: price              # необязательно: по умолчанию последний слот
  pledged_note: …                 # если были заложенные ночи
  litany_intro: …                 # перед «ценой» всех заложенных воспоминаний, одним абзацем
  closing: …
```

Ночь целиком заложенная (`rules.pledgedNightWhen: [night_pledged == 1]` в `world.yaml`, проверяется по состоянию отчёта) в рассказ не попадает. Страницы ночей в рассказе идут прозой без подписей слотов под мелким «Ночь N» (реальный номер), первая ночь без слота `opening_slot`, ночи с заложенной парой без `litany_slot` (его тексты собирает литания). После «Нового дела» в профиле остаются только `endings.*`: блокнот, папка и пары начинаются заново.

## Часы

`rules.clock: { quality: turn, start: "22:00", step: 30 }` — HUD показывает время вместо номера хода (ход 4 — полночь, ход 6 — час ночи). Это только отображение: цену хода по-прежнему задаёт `rules.onChoice`. Условия по времени пишутся через ход: `turn < 4` — «до полуночи», `turn >= 6` — «после часа ночи».

## Музыка

`rules.tensionWhen: [suspicion >= 2]` — пока все условия верны (И, пустой список запрещён схемой), во время ночи играет тревожная дорожка музыки, иначе спокойная. Это только отображение, как и часы: на титуле, отчёте, утре и концовке музыка всегда спокойная, а на историю и концовки правило не влияет. Условия проверяются валидатором так же, как остальные `rules.*`.

## Фрагмент отчёта

```yaml
- id: client_vivian_default
  slot: client          # id слота из world.yaml report.slots
  priority: 0
  when: [nights >= 1]
  text: Клиентка не назвала имени. Это уже кое-что.
```

Слоты объявляются в `world.yaml`: `report.slots: [{ id: client, label: Клиентка }, …]`. Отчёт считается до сброса run, поэтому условия могут смотреть на run-качества (`clues`, `seen.*`).

Для каждого слота в любой ситуации должен подходить хотя бы один фрагмент: делай фрагмент с `priority: -100` без условий.

## Добавить карточку

1. Открой файл локации в `storylets/` или создай новый.
2. Убедись, что качества есть в `world.yaml`, картинки — в `assets/assets.json`.
3. `bun run validate`. Исправь ошибки: битые id, тупики, недостижимость.
4. `bun test`. Если golden изменился — строка в `docs/golden-changelog.md` в том же коммите (см. `engine-change`).
